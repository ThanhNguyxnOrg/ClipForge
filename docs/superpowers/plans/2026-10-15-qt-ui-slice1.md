# Qt UI Slice 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a CI-built Qt 6 Quick slice-1 app (batch queue + progress/cancel, no waveform) that wraps `EngineFacade` without touching core logic.

**Architecture:** New `apps/qt/` layer: QML single window over a C++ `QAbstractListModel` (row state lives in the model) plus an `EngineBridge` QObject that runs `EngineFacade::run_batch` off the UI thread and forwards progress/cancel via signals and the existing atomic token. CMake gates all of it behind `CLIPFORGE_BUILD_QT_UI` (default OFF); a new CI job installs Qt 6.8.3, builds, lints, tests headless, and uploads a `windeployqt` package.

**Tech Stack:** Qt 6.8.3 (`win64_msvc2022_64` + `qtshadertools`), QML, CMake `qt_add_qml_module`, `install-qt-action@v4`, MSVC on `windows-latest`, C++23.

**Spec:** `docs/superpowers/specs/2026-10-15-qt-ui-slice1-design.md`

## Global Constraints

- No Qt on the dev machine: every Qt compile/test is verified by pushing and watching the CI Qt job green — no task is done until its CI run passes.
- Qt layer stays thin: zero audio logic outside `clipforge_core`; `EngineFacade` API is consumed as-is.
- C++23 throughout; MSVC-compatible Qt 6.8 headers per research.
- Repo stays 100% English; QML files pass `qmllint` with zero warnings.
- Existing jobs (ubuntu g++, Windows MSVC+NASM, version check) must stay green.

## Review Focus

- Empty input directory: UI shows an empty queue with an inviting empty-state, no crash — pinned by Task 3 smoke test.
- Cancel mid-batch: rows keep last-known states, run stops after the current file — pinned by Task 2 model test.
- A file that fails mid-batch: its row shows the error, the run continues, summary counts it failed — pinned by Task 2 bridge test with a corrupt WAV fixture.
- Directory containing non-WAV files: ignored silently, never listed, never crash — pinned by Task 2 model test.
- 500-file batch: `ListView` stays smooth (model roles only, no per-row work) — pinned by Task 3 headless startup with a synthetic 500-row model.

### Task 2: C++ bridge + queue model + headless tests

**Files:**
- Create: `apps/qt/EngineBridge.hpp`, `apps/qt/EngineBridge.cpp`
- Create: `apps/qt/BatchQueueModel.hpp`, `apps/qt/BatchQueueModel.cpp`
- Create: `apps/qt/main.cpp` (minimal `QGuiApplication` + `QQmlApplicationEngine` loading `qrc:/Main.qml`; real QML arrives in Task 3 — engine load failure is acceptable until then, the C++ unit tests are this task's gate)
- Create: `apps/qt/tests/tst_bridge.cpp` (QTest)
- Modify: `CMakeLists.txt` (static lib `clipforge_qt` + `clipforge-ui` exe via `qt_add_executable` + test via `add_test`, all inside the Qt block)

**Interfaces:**
- Consumes: `EngineFacade::run_batch`, `BatchRequest`, `ProgressCallback`, atomic cancel token (existing signatures, unchanged).
- Produces:
  - `EngineBridge : QObject` — `Q_INVOKABLE startBatch(QString inputDir, QString outputDir, QString operation, double targetDbfs, double thresholdDbfs, bool recursive, bool dryRun)`, `Q_INVOKABLE cancel()`; signals `fileProgress(int completed, int total, QString currentFile)`, `totalProgress(int completed, int total)`, `batchFinished(bool ok, QString message)`, `batchError(QString message)`. Terminal contract: every run ends with `batchFinished`; `batchError` is informational. Runs `run_batch` on a worker thread; `cancel()` sets the atomic token; batch stops after the current file.
  - `BatchQueueModel : QAbstractListModel` — roles `FileNameRole = Qt::UserRole + 1, StatusRole, ProgressRole, ErrorRole` with `roleNames()` `{"fileName", "status", "progress", "errorMessage"}`; slots `setFiles(QStringList)`, `updateProgress(int row, double progress)`, `setRowError(int row, QString)`, `clear()`. Status values: `"pending"`, `"active"`, `"done"`, `"failed"`, `"cancelled"`.

- [ ] **Step 1: Write failing QTest `tst_bridge.cpp`**

Tests: `init-empty-model` (rowCount 0), `cancel-marks-rows-cancelled` (200 rows, cancel on first progress → zero pending/active), `failed-file-continues` (corrupt WAV row ends `"failed"` with message while siblings end `"done"`, run terminates via `batchFinished(true, ...)`), `non-wav-ignored` (directory with `.txt` yields rowCount 1), `run-batch-synchronous` (direct `run_batch` call, no threads). Fixture: tiny Float32 WAVs via `WavWriter::write_file` into `QTemporaryDir`.
